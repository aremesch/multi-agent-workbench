# Capture spawn-shell exit code + stderr for opaque-death diagnosis

## Context

User originally hit:

```
spawnFailed: Command failed with exit code 1: tmux -L maw pipe-pane -t maw-agent-01KS7ARDXX4PWZW9KNH10E3WSG 'cat >> "/tmp/maw-fifos/fifo-01KS7ARDXX4PWZW9KNH10E3WSG"'
can't find pane: maw-agent-01KS7ARDXX4PWZW9KNH10E3WSG
```

That specific symptom is **already fixed** by commit
[32b36ed (fix(claude-code): stop spawn-time 401 — drop empty API key, share .credentials.json)](https://github.com/anthropics/multi-agent-workbench/commit/32b36ed)
and detailed in
[docs/plans/v0.3-fix-claude-code-spawn-fails-with-401-empty-api-key-stale-cop.md](docs/plans/v0.3-fix-claude-code-spawn-fails-with-401-empty-api-key-stale-cop.md).
Mechanism: MAW had no `ANTHROPIC_API_KEY` configured, so the adapter
substituted `{{env.ANTHROPIC_API_KEY}}` to `''` and the tmux shell line shipped
`ANTHROPIC_API_KEY=""`. claude-code v2.1.148 treats a set-but-empty key as an
explicit (invalid) bearer token, skips OAuth fallback, gets 401 on first
request, and exits — the pane process dies, tmux destroys the session, and
the immediate-next `pipe-pane` call from `runtime.start()` can't find the
pane anymore.

What's still missing — and what this plan ships — is the diagnostic
plumbing that would have made *that* postmortem instant. Today nothing
captures the spawn shell's exit code or stderr, so an opaque spawn death
surfaces as the generic `can't find pane` regardless of whether the cause
is 401, missing PATH, a malformed flag, a broken plugin, or anything else.
The v0.3 mass-death incident plan already called this out (§B-1 of
[docs/plans/v0.3-mass-agent-death-incident-investigation-remediation.md](docs/plans/v0.3-mass-agent-death-incident-investigation-remediation.md))
but the work was never picked up; the 401 fix would have landed in minutes
instead of an investigation cycle if it had been.

**Goal of this PR:** for any future spawn that dies between `tmux
new-session` and `tmux pipe-pane`, the error surfaced to the UI / log
includes the actual exit code and first line of stderr from the spawned
shell. No behavior change for healthy spawns.

## Plan

### 1. Sidecar stdout-isolated exit + stderr capture in the spawn shell line

[TmuxSession.ts:98-116](src/lib/server/tmux/TmuxSession.ts:98) currently builds:

```sh
cd <cwd> && exec env <vars> <cmd> <args>
```

Change to:

```sh
cd <cwd> && env <vars> <cmd> <args> 2>"<exitDir>/spawn.err" ; ec=$?; printf "%s\n" "$ec" > "<exitDir>/exit"; exit $ec
```

Notes:

- Drop `exec`. With `exec`, sh replaces itself with `env`/the CLI, so we
  never get to inspect `$?`. Without `exec`, sh stays alive long enough to
  write the sidecar files, then exits with the same code so tmux still
  tears the session down on death (and on clean exit). One extra
  short-lived `sh` per agent — negligible.
- stdout stays connected to the tmux pane — that *is* the terminal stream
  the user sees. Only stderr is duped to the sidecar; for claude-code
  specifically, fatal errors print to stderr before exit (the 401 case
  prints "Please run /login · API Error: 401 ..."), so stderr is the
  right channel.
- Sidecar dir: `<cfg.dataDir>/agents/<agentId>/spawn/` — sibling to the
  existing `claude/` per-agent dir created by `claudeConfigDir.ts`. Same
  parent (`<cfg.dataDir>/agents/<agentId>/`) means the existing
  `rmdirSync(parent)` cleanup at
  [claudeConfigDir.ts:148](src/lib/server/agents/claudeConfigDir.ts:148)
  naturally clears the parent once both children are gone.

### 2. Read sidecar in `finishAsExited` + when `pipePane` fails

Two consumers:

**a. `finishAsExited`** ([AgentSupervisor.ts:433](src/lib/server/agents/AgentSupervisor.ts:433))

After `runtime.stop()`, before the status flip, read
`<exitDir>/exit` and the last ~4 KiB of `<exitDir>/spawn.err`. Call
[`closeAgentRun(runId, ended_at, exit_code, reason)`](src/lib/server/db/queries.ts:779) —
the helper already exists and is unit-tested but is never called in
production. `reason` is the first non-empty line of `spawn.err` truncated
to 500 chars, falling back to `"exit_code=<n>"` when stderr is empty.

**b. `spawn()` after `runtime.start()` rejects**
([AgentSupervisor.ts:702-703](src/lib/server/agents/AgentSupervisor.ts:702))

This is the path that surfaced the user's original report. Wrap the
`runtime.start()` call: on throw, read `<exitDir>/spawn.err`, log
`console.error('[AgentSupervisor] spawn shell died before pipe-pane:
agentId=<id> exit=<n> err=<first line>')`, and re-throw an Error whose
message embeds the same fields. The
[spawnFromInputs.ts:418-425](src/lib/server/agents/spawnFromInputs.ts:418)
catch already wraps anything from `supervisor.spawn` into a
`spawnFailed` SpawnError, so the message propagates through to the
queue scheduler's `formatError` and to the UI's spawn-error toast
without any other layer changes.

### 3. Wire the run row through so `closeAgentRun` has something to close

[`insertAgentRun`](src/lib/server/agents/AgentSupervisor.ts:707) currently
runs *after* `runtime.start()`. A spawn-shell death (the case we are
trying to capture) never reaches it, so `closeAgentRun` would have
nothing to close.

Move the insert to *before* `Tmux.newSession`, matching the
browser-agent fast-path pattern at
[AgentSupervisor.ts:541-546](src/lib/server/agents/AgentSupervisor.ts:541)
which already inserts the run row before any external launch. If
`newSession` itself throws (tmux server down etc.) we'd then have a run
row with no exit code; that's fine — the existing reaper or a deliberate
"spawn never started" path can close it with a synthetic reason on the
next supervisor init.

Stash the new `runId` on the `AgentRuntime` so `finishAsExited` can pass
it to `closeAgentRun` without an extra DB lookup. (Lookup by `agent_id`
is also fine — small indexed table — pick whichever reads cleaner during
implementation.)

### 4. Cleanup symmetry

In `finishAsExited` and `kill`, after reading the sidecar, remove
`<exitDir>` via `rmSync({ recursive: true, force: true })`. Pair it with
the existing
[`removeAgentClaudeConfigDir(agentId)`](src/lib/server/agents/claudeConfigDir.ts:129)
call so the agent's parent dir empties out and gets rmdir'd by the
existing best-effort cleanup at
[claudeConfigDir.ts:148](src/lib/server/agents/claudeConfigDir.ts:148).
Easiest factoring: extend `removeAgentClaudeConfigDir` (or rename it to
`removeAgentScratchDir` if that reads better) to delete *both* `claude/`
and `spawn/` under the same agent parent, since the parent cleanup is
already its responsibility. One callsite already; both branches
(`finishAsExited`, `kill`) already invoke it.

### 5. Out of scope (deliberately)

- §B-3 (RSS sampling), §B-4 (terminal-tail postmortem on death), §B-5
  (orphan `fifo-test-*` cleanup), §C (systemd memory accounting) from
  the v0.3 mass-death plan. Each is independently useful but
  independently scoped — they should not block this PR.
- `remain-on-exit` on tmux panes. Would keep dead panes addressable for
  `capture-pane` after the command exits, but turns the dashboard into a
  ghost-session graveyard unless we also build a "tombstone" UI. Bigger
  call than this PR can carry.
- Capturing claude-code's *stdout* to the sidecar. Stdout is the TUI;
  intercepting would break the live terminal stream. The FIFO already
  receives it once `pipe-pane` succeeds; the not-yet-piped first frames
  are an accepted small loss in the pre-pipePane-death window.

## Verification

1. **Unit test — `Tmux.newSession` shell-line shape:** extend
   [TmuxSession.test.ts:59](src/lib/server/tmux/TmuxSession.test.ts:59)
   to assert the line no longer starts with `exec`, contains
   `2>".../spawn.err"`, and ends with the `printf … > .../exit; exit $ec`
   suffix.
2. **Unit test — `finishAsExited` reads the sidecar:** mock FS, write a
   fake `exit` (=42) and `spawn.err` (multi-line, first line
   `Boom: bad thing`). Assert `closeAgentRun` is called with
   `exit_code=42` and `reason="Boom: bad thing"`.
3. **Unit test — spawn-fail wrap:** mock `Tmux.pipePane` to throw
   `can't find pane`. Pre-write a sidecar `exit=127` and
   `spawn.err="sh: 1: claude: not found"`. Assert the Error rethrown
   from `supervisor.spawn` contains both `exit=127` and the stderr
   line. Assert `spawnFromInputs` then surfaces it under
   `code: 'spawnFailed', message: '<...rich message...>'`.
4. **E2E — deliberate spawn failure:** add a temporary role pointing at
   `command: "nonexistent-cli"`. Spawn from the UI. The toast/log shows
   `exit=127 err="sh: 1: nonexistent-cli: not found"`, not
   `can't find pane`. Confirm `agent_runs.exit_code = 127` and `reason`
   is set on the row.
5. **E2E — clean exit retains observability:** spawn a `bash` agent
   (smoke role), `Ctrl-D` inside. Confirm `agent_runs.exit_code = 0`
   and `reason` is empty or `exit_code=0`. No regression in normal
   shutdown.
6. **E2E — reproduce 32b36ed in a temporary regression:** roll back
   32b36ed *in a scratch branch* (leave `ANTHROPIC_API_KEY=""` going to
   the spawn env), keep this PR's instrumentation, spawn a claude-code
   agent. The error message must now contain the 401 stderr line — the
   diagnostic plumbing should make that root cause obvious on first
   read. Don't merge the rollback; this is just confirmation that the
   instrumentation does its job.
