# Polyrepo Workspace Support

## Context

MAW models a **Project** as just a label over individually-registered repos. Users
frequently work on several *linked but independent* git repos that live as siblings
under one shared parent directory (a **polyrepo** layout — NOT a monorepo), e.g.:

```
~/smb/ar/workspace/portfolio/
  portfolio-tracker-2025/.git
  portfolio-import/.git
  tresor-import/.git
```

Today each repo must be attached one path at a time via
`projects/[id]/repos/new`. The goal: register a whole workspace folder's sibling
repos under one Project in a single batch action, remember the shared parent path
(the **workspace root**) on the Project, and surface the grouping on the project
page. The existing single-repo flow must keep working unchanged.

**Naming:** the shared parent dir is the `workspace` / `workspace_root`; the
grouping stays a `project`. Never "monorepo".

## Scope guards (from task)

- No cross-repo agent visibility / shared worktrees — agents still spawn per-repo.
- No filesystem auto-scan or watching — batch import is strictly user-initiated.
- Do **not** touch `src/lib/components/ui/` (none exist yet anyway; the real
  components live in `src/lib/client/components/`).
- Extend the existing data model; do not refactor it.

## Design decisions (confirmed with user)

- **Dedicated full page** `projects/[id]/repos/import`, mirroring the existing
  single add-repo page (`load` + form `action`, no new client API endpoint).
  Discovery is driven by a `?workspace=<abs-path>` URL param read in `load`.
- **Partial failure = import the good ones, report the rest.** Repos that pass
  validation are registered and `workspace_root` is set; repos that fail git
  normalization are listed back with their reason instead of redirecting.

## Implementation

### 1. Schema — migration `013`

New file `migrations/013_project_workspace_root.sql`. Add a nullable column; no
table rebuild needed (additive `ALTER`):

```sql
-- Add the optional shared-parent ("workspace root") path to projects.
-- Nullable: not every project is a polyrepo workspace. Set on first batch
-- import from a workspace folder.
ALTER TABLE projects ADD COLUMN workspace_root TEXT;
```

Migration runner (`src/lib/server/db/migrate.ts`) auto-discovers `NNN_*.sql` by
SHA256 — nothing else to wire. The test DB helper (`tests/unit/helpers/db.ts`)
applies all migrations, so tests pick it up automatically.

### 2. Types + queries

- `src/lib/server/db/types.ts` (~L61) — add `workspace_root: string | null;` to
  `ProjectRow`.
- `src/lib/server/db/queries.ts` — `getProject`/`listProjects` use `SELECT *`, so
  reads need no change. Add one writer next to `insertProject`:

  ```ts
  export function setProjectWorkspaceRoot(
    id: string, userId: string, workspace_root: string
  ): boolean // UPDATE projects SET workspace_root=?, updated_at=? WHERE id=? AND user_id=?
  ```

  Leave `insertProject` untouched (workspace_root defaults NULL on create).

### 3. Discovery helper (reused + unit-tested)

Add to `src/lib/server/fs/browse.ts`, built on the existing `listDirectory()`
(which already flags `.git` children via `isGitRepo`):

```ts
export interface GitRepoChild { name: string; path: string; }
export function listGitRepoChildren(
  requested: string, root: string
): { path: string; children: GitRepoChild[] }
```

It calls `listDirectory(requested, root)`, keeps only `entries.isGitRepo`, and
returns absolute child paths (`join(result.path, name)`). Sandbox clamping +
symlink-escape protection come for free from `listDirectory`. This single helper
backs both the page's `load` discovery and the action's per-path re-validation
(DRY — the action never trusts the client's path list).

### 4. Batch-import page — `src/routes/projects/[id]/repos/import/`

**`+page.server.ts`**

- `load`: auth + ownership (mirror existing `repos/new` load). Read
  `url.searchParams.get('workspace')`. If absent → return `{ project, repos: null }`.
  If present → `listGitRepoChildren(workspace, getFsBrowseRoot())`, compute which
  child paths are already registered (compare against `listReposForProject(id)`
  paths), and return `{ project, workspace, repos, registeredPaths }`. Map
  `BrowseError` codes to the existing `picker.error.*` / `common.error.*` keys.
- `actions.default`: auth + ownership. Read `workspace_root` and
  `form.getAll('paths')` (multiple hidden inputs). Re-discover git children of
  `workspace_root` via the helper and **intersect** the submitted paths with that
  set (reject anything not a real git child / already registered). For each
  surviving path, reuse the existing normalization from `repos/new/+page.server.ts`:
  `WorktreeManager.ensureDefaultBranch(path, project.default_branch, identity)` —
  on `no_master` record a per-path failure; on success `insertRepo({ …, project_id,
  default_branch: project.default_branch })`. Identity via
  `resolveGitIdentity(...)`. After the loop, if ≥1 imported and the project has no
  `workspace_root` yet, call `setProjectWorkspaceRoot`. Redirect to
  `/projects/{id}` only when there were **no** failures; otherwise
  `fail(400, { workspace, imported: string[], errors: {path,error}[] })` so the
  page redisplays results. Dedup already-registered paths silently (skip, not error).

**`+page.svelte`** (reuse conventions from `repos/new` + `DirectoryPickerDialog` +
the checkbox-list pattern in `SpawnAgentForm.svelte` L1094–1109)

- "Choose workspace folder" button → opens `DirectoryPickerDialog` (single-select,
  already returns a `path`). `onSelect` → `goto(\`?workspace=\${encodeURIComponent(path)}\`)`
  (import `goto` from `$app/navigation`) to trigger `load` discovery.
- When `data.repos` present: render the resolved workspace path, then a checkbox
  list of discovered repos (`name` + muted `path`); entries in
  `data.registeredPaths` are shown checked + disabled ("already added"). A
  select-all toggle. Selected paths go into the POST as repeated
  `<input type="hidden" name="paths">` plus a hidden `workspace_root`.
- After a partial-failure `fail()`, show the `imported` count and an error list
  (`form.errors`) — consistent loading/error states with the rest of the app.

### 5. Project detail view — `src/routes/projects/[id]/+page.svelte`

- If `data.project.workspace_root` is set, show it at the top (under the header,
  e.g. a muted "Workspace: `<path>`" line).
- Add a CTA next to the existing "New repo" button:
  "Add repos from workspace folder" → links to `…/repos/import`. Label adapts
  ("Add more…" when a workspace_root already exists). The single-repo "New repo"
  link stays. No `+page.server.ts` change needed (`getProject` already returns the
  new column).

### 6. i18n

Add keys to **all four** locale files (`src/lib/i18n/{en,de,es,fr}.ts`) — the repo
keeps them in sync. New namespace `import.*` (e.g. `import.title`,
`import.chooseFolder`, `import.workspaceLabel`, `import.discovered`,
`import.alreadyAdded`, `import.selectAll`, `import.attachSelected`,
`import.importedCount`, `import.noGitChildren`) plus `projects.addFromWorkspace` /
`projects.addMoreFromWorkspace` and `projects.workspaceRoot`. Reuse existing
`common.error.path*` and `picker.error.*` for validation messages.
