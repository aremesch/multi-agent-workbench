# Fix: claude-code spawn fails with 401 — empty API key + stale copied credentials

> **Pre-implementation rename (per global plan rules):**
> - file → `docs/plans/v0.3-claude-code-spawn-401.md`
> - branch → `fix/v0.3-claude-code-spawn-401`

## Context

Production symptom: spawning a fresh `claude-code` agent prints the banner, but the first API call returns:

```
⎿  Please run /login · API Error: 401 Invalid authentication credentials
```

The failing tmux command shows the smoking gun:

```
env ANTHROPIC_API_KEY="" MAW_AGENT_ID="..." ... CLAUDE_CONFIG_DIR="..." "claude" ...
```

`ANTHROPIC_API_KEY` is **set to the empty string**, not unset. claude-code v2.1.148 treats a set-but-empty `ANTHROPIC_API_KEY` as an explicit (invalid) bearer key and never falls back to the OAuth credentials in `.credentials.json` — so the request goes out with `Authorization: Bearer ` and the API returns 401.

Why didn't this hit before the recent mass-death fix ([v0.3-mass-agent-death-incident-investigation-remediation](docs/plans/done/v0.3-mass-agent-death-incident-investigation-remediation.md), commit e1935a1)? Pre-fix, the user-global `~/.claude/.credentials.json` was shared by every spawn and the running CLI was already authenticated against it; the empty env var was an inert footgun. Post-fix, each spawn starts cold in an isolated `CLAUDE_CONFIG_DIR` and now respects the set-but-empty env var over the seeded creds.

### Data flow that produces the empty string

1. [src/lib/server/config.ts:102](src/lib/server/config.ts:102) — `anthropicApiKey: env.ANTHROPIC_API_KEY ?? ''` (becomes `''` when MAW's own env doesn't set it)
2. [src/lib/server/agents/AgentSupervisor.ts:593](src/lib/server/agents/AgentSupervisor.ts:593) — passes `ANTHROPIC_API_KEY: cfg.anthropicApiKey` to `adapter.buildSpawnSpec(opts.env)`
3. [cli-adapters/claude-code.jsonc:44](cli-adapters/claude-code.jsonc:44) — declares `"env": { "ANTHROPIC_API_KEY": "{{env.ANTHROPIC_API_KEY}}" }`
4. [src/lib/server/agents/adapters/ConfigDrivenAdapter.ts:194-197](src/lib/server/agents/adapters/ConfigDrivenAdapter.ts:194) — substitutes `{{env.ANTHROPIC_API_KEY}}` → `''` and unconditionally writes it to `resolvedEnv`
5. [src/lib/server/tmux/TmuxSession.ts:98-102](src/lib/server/tmux/TmuxSession.ts:98) — emits the `env KEY="value"` shell line; the empty string is preserved verbatim as `ANTHROPIC_API_KEY=""`

## Fix

Two changes, both required:

**(1)** stop passing `ANTHROPIC_API_KEY=""` to the spawn (the immediate 401 cause), and
**(2)** stop copying `.credentials.json` per-agent — symlink it instead, so every agent reads the same live OAuth state and refresh-token rotation can't strand later spawns with an already-invalidated token.

### Change 1 — drop empty env entries in the adapter

Drop env entries whose substituted value is empty. One layer, one place: the adapter is the only component that knows which keys are templated from process env (so an empty value means "the user didn't configure this") vs literal — anywhere else would either over-special-case the API-key triplet or hide future deliberate `""` configurations behind a transport filter.

[src/lib/server/agents/adapters/ConfigDrivenAdapter.ts:194-197](src/lib/server/agents/adapters/ConfigDrivenAdapter.ts:194) — current:

```ts
const resolvedEnv: Record<string, string> = {};
for (const [k, v] of Object.entries(this.cfg.spawn.env)) {
  resolvedEnv[k] = subst(v);
}
```

becomes:

```ts
const resolvedEnv: Record<string, string> = {};
for (const [k, v] of Object.entries(this.cfg.spawn.env)) {
  const resolved = subst(v);
  // Skip vars that resolved to empty — typically a templated `{{env.X}}`
  // where X is unset. Passing `KEY=""` would override fallback auth
  // (e.g. claude-code's seeded OAuth in .credentials.json).
  if (resolved === '') continue;
  resolvedEnv[k] = resolved;
}
```

`MAW_AGENT_ID`/`MAW_URL`/`GIT_*`/`CLAUDE_CONFIG_DIR` merged in at [AgentSupervisor.ts:662-680](src/lib/server/agents/AgentSupervisor.ts:662) are untouched — they're computed locally, always non-empty, and an empty there would be a bug worth surfacing, not silencing.

### Change 2 — symlink `.credentials.json` instead of copying

The copy-per-spawn pattern locks each agent to whatever OAuth state existed in `~/.claude/.credentials.json` at the moment of its spawn. If a previously-running agent later refreshes its access token (claude-code rewrites `.credentials.json` via atomic rename at refresh time) and that rewrite happens to land in its **own** per-agent copy, the user-global source stays stale. Worse, if claude-code's OAuth server returns a rotated refresh token on use (single-use rotation is a defensive default for many OAuth providers, and the v2.x CLI doesn't document which it expects), the second agent's seeded refresh token is already dead — and that's the 401 the user is seeing now persists even after change 1, for any agent spawned more than `<access-token-ttl>` after the previous one.

A symlink fixes both: every agent reads and writes the **same** file, refreshes become observable to all running and future agents, and seeding can never produce a stale snapshot.

In [src/lib/server/agents/claudeConfigDir.ts:49-61](src/lib/server/agents/claudeConfigDir.ts:49) move `.credentials.json` from `SEED_FILES` to `SEED_SYMLINKS`:

```ts
const SEED_FILES: Array<{ src: string; dest: string }> = [
  { src: '.claude.json', dest: '.claude.json' },
  { src: '.claude/CLAUDE.md', dest: 'CLAUDE.md' },
  { src: '.claude/settings.json', dest: 'settings.json' }
];

const SEED_SYMLINKS: Array<{ src: string; dest: string }> = [
  { src: '.claude/.credentials.json', dest: '.credentials.json' },
  { src: '.claude/plugins', dest: 'plugins' },
  { src: '.claude/plans', dest: 'plans' }
];
```

The existing symlink loop at [claudeConfigDir.ts:96-113](src/lib/server/agents/claudeConfigDir.ts:96) handles files just as well as directories on POSIX (the `'dir'` type hint on line 106 is a Windows-only disambiguator that the kernel ignores on Linux). `rmSync(destAbs, { recursive: true, force: true })` on line 105 correctly unlinks a prior symlink or copied file without descending — same semantic that already protects `~/.claude/plugins/`.

Update the doc comment block at [claudeConfigDir.ts:17-25](src/lib/server/agents/claudeConfigDir.ts:17) to reflect the new partition (`.credentials.json` moved into the "symlinked, shared across agents" bucket).

#### Race surface

Concurrent refresh is the only race introduced by sharing this file. claude-code's standard write pattern is `tmp → rename`, so a partial-write half-state isn't observable. The remaining hazard: two agents call the OAuth refresh endpoint within the access-token-TTL boundary, and the provider invalidates the refresh token after the first call. The losing agent gets 401 once, and the winner's freshly-written refresh token is then available to both. Acceptable: bounded blast radius (a single 401 inside one agent, recoverable by user retry), no cross-agent crash. The mass-death pattern that motivated `CLAUDE_CONFIG_DIR` isolation was about **`.claude.json`** being rewritten while other CLIs had it mmap'd/watched — `.credentials.json` is a tiny lazily-read JSON blob with no such hot path, so the same failure mode does not apply.
