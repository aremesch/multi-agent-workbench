# Spawn error diagnostics + state cleanup

## Context

Starting an agent for a task with a long initial prompt fails with:

```
spawnFailed: Command failed with exit code 1:
tmux -L maw pipe-pane -t maw-agent-01KS5STEJBBBBW5YMS5M2WEWFX
  'cat >> "/tmp/maw-fifos/fifo-01KS5STEJBBBBW5YMS5M2WEWFX"'
can't find pane: maw-agent-01KS5STEJBBBBW5YMS5M2WEWFX
```

The pane is missing because the agent CLI process exited within
microseconds of being exec'd by `sh -lc`, and tmux destroyed the empty
session before `Tmux.pipePane()` ran. Root cause is *not* a tmux race —
`tmux new-session -d` returns only after the pane is created. The CLI
itself died on launch.

For a very long prompt the most plausible reason is that `claude` (or
another adapter CLI) crashes/exits when handed an oversized positional
prompt arg. ARG_MAX on this host is ~3.2 MB so it isn't a kernel argv
cap — it's a CLI-internal limit or input parsing error. Today we can't
tell, because by the time we look the session is already gone and no
output was captured.

A second, separate problem: when `supervisor.spawn` throws,
`performSpawn` returns `spawnFailed` but leaves three artifacts behind —
the on-disk worktree, the `worktrees` row, and the `agents` row (status
= `spawning`). The next retry with the same task title hits
`titleTaken` until the user cleans up by hand.

Goals of this change:

1. Surface what the dying CLI actually printed (so "prompt too long",
   "binary not found", "missing API key", etc. become visible).
2. Roll back on-disk + DB state on spawn failure so retries work.
3. Don't disrupt the existing happy-path exit detection.

## Approach

Use tmux's `remain-on-exit failed` window option: a pane whose program
exits with non-zero stays alive in a "dead" state, so we can capture
its scrollback before tearing it down. On a normal zero-exit (user
quits cleanly) the pane closes as before and the existing
`session-closed` hook fires, so exit detection is unchanged.

For abnormal exits we install a global `pane-died` hook that signals
the same wait-for channel the `session-closed` hook already uses, so
the existing exit-watcher path resolves uniformly whether the pane
closed normally or stayed as a dead pane.

After `Tmux.newSession()` the supervisor verifies the pane is alive
(`#{pane_dead}` is `0`). If it's dead, we capture the pane's last
output, kill the session, and throw a `spawnFailed` error whose
`message` carries the captured output for the UI to show.

On any throw out of `supervisor.spawn`, `performSpawn` now rolls back
the worktree dir, the worktree row, and the agent row before returning
the error.

## Changes

### 1. `src/lib/server/tmux/TmuxSession.ts`

Add three new static methods:

- `ensureSpawnDiagnosticsHooks()` — idempotent, called from
  `AgentSupervisor.init()` alongside `ensureGlobalSessionClosedHook`.
  Installs:
  - `set-window-option -g remain-on-exit failed`
    (default for all new windows on the `maw` socket)
  - `set-hook -g pane-died 'run-shell -b "tmux -L maw wait-for -S
    maw-exit-#{hook_session_name}"'`
    (mirrors the existing `session-closed` hook so the same wait-for
    channel fires whether the pane dies-and-stays or fully closes)

- `isPaneDead(session): Promise<boolean>` —
  `tmux display-message -t SESSION -p '#{pane_dead}'` → returns true
  when the value is `"1"`. Returns true on "can't find session" (gone
  is dead). Returns false on any other error so we don't spuriously
  abort spawn.

- `captureDeadPaneTail(session, lines = 200): Promise<string>` —
  wraps `capturePane(session, -lines)`; trims ANSI escapes and trailing
  blank lines. Used only for the diagnostic error message, so keep it
  small and best-effort (catch and return `""` on any failure).

### 2. `src/lib/server/agents/AgentRuntime.ts`

In `start()`, between `fifo.start(...)` and `Tmux.pipePane(...)`, call
a new private `verifyPaneAlive()` helper:

- Poll `Tmux.isPaneDead(this.agent.tmux_session)` at 0, 25, 75, 150 ms
  (four tries, ~250 ms ceiling).
- If any poll returns "dead", capture the tail via
  `Tmux.captureDeadPaneTail`, `Tmux.killSession`, and throw an `Error`
  whose message is:
  `agent process exited immediately on launch — captured output:\n<tail>`
  (or "no output captured" if the tail is empty — typical for a
  command-not-found before the shell ever printed).
- If all polls return alive, fall through to `Tmux.pipePane`.

Why in `AgentRuntime.start` rather than directly after `newSession` in
`AgentSupervisor.spawn`: keeps the supervisor's spawn block lean and
reuses the runtime's own teardown error path. The throw propagates up
to `supervisor.spawn`'s caller as expected.

### 3. `src/lib/server/agents/AgentSupervisor.ts`

- In `init()`, call `Tmux.ensureSpawnDiagnosticsHooks()` next to the
  existing `Tmux.ensureGlobalSessionClosedHook()` call (around
  line 255). Same error-tolerant pattern.
- If `runtime.start()` throws (the new pane-dead path), `supervisor.spawn`
  must still throw, but should also `await Tmux.killSession(...)` for
  safety and `deleteAgent(agentId)` so the orphan row doesn't linger.
  Wrap the existing `await runtime.start()` in try/catch around lines
  686–690, re-throw after cleanup.

### 4. `src/lib/server/agents/spawnFromInputs.ts`

Replace the bare `catch` around the `supervisor.spawn(spawnArgs)` call
(lines 418–425) with a cleanup block:

- If `worktreePath` was created by this call (i.e.
  `v.shouldCreateWorktree` was true): `WorktreeManager.remove({
  repoPath: v.repo.path, wtPath: worktreePath, force: true })`.
  Wrap in try/catch — best-effort cleanup, do not mask the original
  spawn error.
- `updateWorktreeStatus(worktreeId, 'removed')` so the worktree row
  doesn't show as active in the dashboard.
- The agent row deletion is handled by step 3 inside `supervisor.spawn`.

Return `{ ok: false, error: { code: 'spawnFailed', message } }` with
the message already enriched by step 2's throw.

### 5. i18n (light touch)

The `spawn.error.spawnFailed` label is already wired in
`src/lib/i18n/{en,de,es}.ts`. The new captured-output prefix appears in
the *message* (rendered as detail below the label by the spawn form);
no new keys needed. Confirm the form action at
`/routes/agents/new/+page.server.ts:155` actually surfaces
`result.error.message` to the user — if it currently swallows it, also
add a `details` field to the JSON response there.

## Verification

End-to-end with `pnpm dev`:

1. **Long-prompt repro** — temporarily lower the test by spawning
   `claude` with a deliberately huge positional prompt (e.g. paste a
   500 KB markdown blob in the task body). Before this plan: cryptic
   `can't find pane`. After: error message contains the captured tail
   ("Argument list too long" / "request payload too large" / whatever
   claude prints), worktree dir is gone, the agent row is gone, and
   retrying the same task title succeeds without a `titleTaken`.
2. **Binary-missing repro** — point a role at a non-existent CLI
   command (`spawn.command = "nope"` in a temporary adapter). Expected
   tail: `sh: nope: command not found`. Same cleanup behavior.
3. **Happy path** — spawn a normal short-prompt agent. The pane is
   alive, `verifyPaneAlive` returns clean, pipe-pane runs as before,
   `session-closed` hook still fires on normal exit, the dashboard
   moves the agent to the archive.
4. **User-quit path** — spawn an agent, then exit cleanly (Ctrl-D in
   the CLI). Pane closes (rc=0), session closes,
   `session-closed` hook signals — existing exit watcher resolves.
   Verify the archive entry appears.
5. **Abnormal-exit-after-running path** — spawn an agent, then kill
   its child process with non-zero rc *after* it's been running for a
   while (e.g. `kill -9` from outside). The pane goes dead and
   `pane-died` hook fires the wait-for channel; the existing exit
   watcher resolves. Verify the archive entry appears and no zombie
   session lingers (`tmux -L maw list-sessions` is clean).

Run unit tests: `pnpm test src/lib/server/tmux src/lib/server/agents`.
The existing `TmuxSession.test.ts` should be extended with cases for
the new hook installer and for `isPaneDead` / `captureDeadPaneTail`.
The supervisor and spawnFromInputs tests should pick up cleanup
assertions on the failure path.

## Out of scope

- A hard cap or warning on prompt length in the spawn form. The
  diagnostic message will guide users; a UI cap is a separate UX
  decision.
- Migrating exit detection wholesale to `pane-died` only. The dual
  hook (session-closed + pane-died both signaling the same channel) is
  sufficient and keeps the existing-session reattach logic unchanged.
- Adding a "view tail" affordance on the archive page for failed
  spawns. The error message + toast is enough for now; if the user
  wants a permanent record we'd persist `tail` on a failed-agent row.
