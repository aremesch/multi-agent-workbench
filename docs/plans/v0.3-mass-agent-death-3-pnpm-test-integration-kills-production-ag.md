# Mass agent-death #3 — `pnpm test:integration` kills production agents

## Context

Today (2026-05-22 15:53:19 local / 13:53:19 UTC), **three** claude-code agents
died simultaneously on the production maw host while the user reported the
incident from the surviving agent (`fix-agent-exit-notification`). The dead
agents were `fix-agent-state-inconsistency`
(`01KS7Y89JMY03HKRD2FRNRH9JE`), `fix-title-taken-error`
(`01KS7XTFXEFQ0A7NZHVPFZ25B8`), and a long-running zombie from May 21
(`01KS66C1RB2WRMRKZBPVS3PEAX`). Survivor: `fix-agent-exit-notification`
(`01KS7Z1YVE3A76ECCJ001NPGK0`).

This is the third occurrence of the same symptom. The first two
(2026-05-21 22:03 — six agents) were diagnosed in
[docs/plans/done/v0.3-mass-agent-death-incident-investigation-remediation.md](docs/plans/done/v0.3-mass-agent-death-incident-investigation-remediation.md)
and partially fixed by [src/lib/server/agents/claudeConfigDir.ts](src/lib/server/agents/claudeConfigDir.ts):
every `claude-code` agent spawn now gets its own `CLAUDE_CONFIG_DIR`,
which is supposed to keep one CLI's startup `rename(2)` of
`~/.claude.json` from yanking the config out from under the others.

That fix works for **agent spawns**, but not for **test spawns**: the
live integration test
[tests/integration/claude-code-live.test.ts](tests/integration/claude-code-live.test.ts)
spawns a real `claude` subprocess outside `AgentSupervisor` and reaches
straight for shared host resources. Today's incident is that test
firing on the production host — almost certainly invoked by one of the
working agents running `pnpm test:integration` to verify its fix, or by
the user manually.

## Two independent kill paths in the test

Both are armed every time the test runs on the host. Either alone is
sufficient to take down production agents; both must be closed.

### 1. `~/.claude.json` atomic-rewrite (root cause, same as incidents #1 + #2)

The test spawns `claude` with **no `CLAUDE_CONFIG_DIR`** in env:

- [claude-code-live.test.ts:286-291](tests/integration/claude-code-live.test.ts:286) — `buildSpawnSpec({env: {ANTHROPIC_API_KEY?}, …})` only carries the API key.
- [claude-code-live.test.ts:300-302](tests/integration/claude-code-live.test.ts:300) — `cleanEnv` filters empty values; result is `{}` or `{ANTHROPIC_API_KEY}`.
- [claude-code-live.test.ts:306-314](tests/integration/claude-code-live.test.ts:306) — `Tmux.newSession({env: cleanEnv, …})` — no override.

So the test `claude` reads/writes `~/.claude.json` (proven by the
shared-tree jsonl and the timestamped backup) and atomically replaces it
during startup. Any running agent that touches the same inode dies in
the next file-refresh / watcher tick.

### 2. `afterEach` mass-kill of `maw-agent-*` tmux sessions

[claude-code-live.test.ts:118-142](tests/integration/claude-code-live.test.ts:118):

```ts
const list = await execa('tmux', ['-L', 'maw', 'list-sessions', '-F', '#{session_name}'], { reject: false });
const sessions = (list.stdout ?? '').split('\n').filter((s) => s.startsWith('maw-agent-'));
for (const s of sessions) {
  await Tmux.killSession(s).catch(() => {});
}
```

Uses the **production** `-L maw` socket and the **production session
prefix** ([TmuxSession.ts:11](src/lib/server/tmux/TmuxSession.ts:11):
`SESSION_PREFIX = 'maw-agent-'`). Whether or not this loop actually
ran today (the scratch-dir leak suggests the test was killed before
`afterEach`), it absolutely would on any clean test pass.

The 2026-05-21 plan called for "Gate the test harness's tmux socket
name behind an env var, never `-L maw` by default. Audit any other test
reaching the production socket." (`v0.3-mass-agent-death-…md`, §B-5).
That follow-up was never implemented.

## Fix — four layers, all in the test except one line in production

### Layer A — Per-test `CLAUDE_CONFIG_DIR`

In [claude-code-live.test.ts](tests/integration/claude-code-live.test.ts):

- `beforeEach`: allocate `claudeConfigDir = mkdtempSync(join(tmpdir(), 'maw-claude-cfg-'))`. Seed it inline (do not import `ensureAgentClaudeConfigDir` — that helper writes under `getConfig().dataDir` which we don't want to bring into the test):
  - `copyFileSync(~/.claude.json, …/claudeConfigDir/.claude.json)` if the source exists. This carries the dev's `hasCompletedOnboarding` flag so the test claude doesn't hit the subscription prompt.
  - `symlinkSync(~/.claude/.credentials.json, …/.credentials.json)` if present — keeps OAuth/keychain auth working without copy-then-stale.
  - `symlinkSync(~/.claude/plugins, …/plugins)` and `~/.claude/plans` — read-mostly shared, matches the production seeding pattern in [claudeConfigDir.ts:69-73](src/lib/server/agents/claudeConfigDir.ts:69).
- `startRuntime` (line 286): add `CLAUDE_CONFIG_DIR: claudeConfigDir` to the env map handed to `buildSpawnSpec`.
- `afterEach`: `rmSync(claudeConfigDir, { recursive: true, force: true })`.

**Why this alone fixes the rewrite-kill:** the test claude reads and rewrites `<claudeConfigDir>/.claude.json` instead of `~/.claude.json`. The host's canonical file is untouched.

### Layer B — Per-test tmux socket

The production `Tmux` module hard-codes `SOCKET = 'maw'`
([TmuxSession.ts:20](src/lib/server/tmux/TmuxSession.ts:20)). Change
that single line:

```ts
const SOCKET = process.env.MAW_TMUX_SOCKET ?? 'maw';
```

Add a short comment warning that `MAW_TMUX_SOCKET` must NOT be set in
`maw.service`'s env — it would orphan every reattach since the
existing tmux server lives on `-L maw`.

In the test, set `process.env.MAW_TMUX_SOCKET = \`maw-test-${process.pid}\``
at the **top of the file**, before the `import { Tmux }` line — vitest
module load order means the constant is fixed at import. Also replace
the five direct `execa('tmux', ['-L', 'maw', …])` calls in this file
(L122, L367, L477, L488, L507, L516) to use the same env-var value.

**Why this matters even with Layer A:** even if A is perfect, the
`afterEach` cleanup is a separate kill mechanism. With a per-pid
socket, the production agent sessions are simply invisible to the
test — `list-sessions` returns only the test's own sessions, and
`killSession` only touches those.

### Layer C — Refuse to run on a production host

In `beforeAll` (around [claude-code-live.test.ts:103](tests/integration/claude-code-live.test.ts:103)):

```ts
const svc = execaSync('systemctl', ['--user', 'is-active', 'maw.service'], { reject: false });
if (svc.stdout?.trim() === 'active') {
  throw new Error('Refusing to run live test on production maw host — see docs/plans/once-again-an-event-humble-catmull.md');
}
// Belt-and-suspenders: also check for any pre-existing maw-agent-* sessions on the
// production socket. Catches dev hosts without systemd that still have agents up.
const list = execaSync('tmux', ['-L', 'maw', 'list-sessions', '-F', '#{session_name}'], { reject: false });
if ((list.stdout ?? '').split('\n').some((s) => s.startsWith('maw-agent-'))) {
  throw new Error('Refusing to run live test: production maw-agent-* tmux sessions detected on -L maw');
}
```

This guard runs **before** any spawn or socket interaction, so a
mis-targeted run aborts before any damage.

### Layer D — Track-and-kill instead of list-and-kill

With Layer B in place, the `afterEach` walker only sees the per-pid
test socket. Tighten it anyway: maintain `const sessionsCreated = new Set<string>()`
populated immediately after `Tmux.newSession(…)` in `startRuntime`. Have
`afterEach` iterate that set instead of listing the socket. Three lines.
Closes the failure mode where a future change accidentally re-uses the
production socket and reintroduces the wide-net kill.

## Verification

End-to-end smoke, in this order:

1. **Production-guard fires.** On the maw host (or any host with the
   maw service active), `pnpm test:integration` MUST exit non-zero
   before touching tmux or spawning claude. `journalctl --user-unit=maw`
   shows no `[AgentSupervisor]` activity around the test run.
2. **Socket isolation works.** On a dev box with no production agents:
   while the test runs, in another shell run
   `tmux -L maw list-sessions 2>&1` (expect empty / "no server") and
   `tmux -L maw-test-$(pgrep -f 'vitest.*integration') list-sessions`
   (expect exactly one `maw-agent-<ulid>` — the test's own).
3. **Config-dir isolation works.** Before/after `stat -c '%y %n' ~/.claude.json`:
   mtime must be unchanged. `find ~/.claude/projects/ -newer …` returns
   nothing test-related. `find $TMPDIR -name 'maw-claude-cfg-*'` shows the
   test's own dir and its own `projects/-tmp-maw-claude-live-*/<sid>.jsonl`.
4. **Co-running agents survive.** On a dev box, spawn a real
   claude-code agent through MAW (via the UI), then run
   `pnpm test:integration`. The agent's `~/.claude.json` mtime must not
   move and its tmux session must remain alive after the test exits.
5. **Existing test functionality preserved.** Test still passes its
   smoke assertions (adapter leaves BOOTING, pane shows `>` / `❯`,
   raw keys flow, exit chord delivered).

## Audit of the rest of the codebase

The user asked for a sweep of every other place that could overwrite
`~/.claude.json` or otherwise kill agents. Findings, by category:

### Other `claude` binary spawns — none

Repo-wide grep for `execa('claude'`, `spawn.*'claude'`, `'claude'.*--`,
`exec.*claude` outside `node_modules`: the **only** non-comment match
is the integration test ([claude-code-live.test.ts:306-314](tests/integration/claude-code-live.test.ts:306)).
Every other claude invocation goes through `AgentSupervisor.spawn`
([AgentSupervisor.ts:583-694](src/lib/server/agents/AgentSupervisor.ts:583)),
which sets `CLAUDE_CONFIG_DIR` at line 693. The cli-adapter
([cli-adapters/claude-code.jsonc:38-40](cli-adapters/claude-code.jsonc:38))
only carries `ANTHROPIC_API_KEY` in `spawn.env` — the supervisor adds
`CLAUDE_CONFIG_DIR` on top.

### Other tmux operations on `-L maw` — present but safer

```
src/lib/server/tmux/TmuxSession.reattach.integration.test.ts:34   const SOCK = `maw-reattach-${process.pid}`;
tests/e2e/agent-lifecycle.spec.ts:19                              const TMUX_SOCKET = 'maw';
tests/e2e/agent-image-upload.spec.ts:?                            const TMUX_SOCKET = 'maw';
tests/e2e/terminal-subscribe.spec.ts:?                            const TMUX_SOCKET = 'maw';
tests/e2e/agent-window-menu.spec.ts:?                             const TMUX_SOCKET = 'maw';
tests/e2e/claude-hook.spec.ts:?                                   const TMUX_SOCKET = 'maw';
```

- **`TmuxSession.reattach.integration.test.ts`** — already isolated:
  `SOCK = maw-reattach-${process.pid}` and `tm('kill-server')` at the
  socket end ([line 61](src/lib/server/tmux/TmuxSession.reattach.integration.test.ts:61)).
  Touches no production state. Pattern to follow elsewhere.
- **Five `tests/e2e/*.spec.ts`** — all use `TMUX_SOCKET = 'maw'`, share
  the production socket. **Less dangerous** than the integration test
  because: (i) they spawn `shell` cli kind (bash, not claude — no
  `~/.claude.json` rewrite path), and (ii) they track sessions they
  created in a local array and only kill *those* by ULID, not
  prefix-matching with a wide net (see
  [agent-lifecycle.spec.ts:195-203](tests/e2e/agent-lifecycle.spec.ts:195)).
  Still, they share the socket — so a clean-slate `tmux kill-server`
  during teardown (none today, but conceivable) would nuke production
  too. Layer B's `MAW_TMUX_SOCKET` env var trivially makes them safe
  by side effect: vitest doesn't run them, but `pnpm test:e2e` sets
  `MAW_TMUX_SOCKET=maw-e2e-${pid}` in the playwright webServer env and
  every `tmux()` helper inherits it.

No other tmux-touching code outside `TmuxSession.ts` and tests.

### Direct writes under `~/.claude/` or `~/.claude.json` — read-only

Grep across the production tree:

- [src/lib/server/agents/history/ClaudeJsonlTokens.ts:57](src/lib/server/agents/history/ClaudeJsonlTokens.ts:57)
  — `readFileSync` on `~/.claude/projects/<encoded-cwd>/<sid>.jsonl`
  as a **back-compat fallback** for archived pre-isolation agents.
  Read-only. Safe.
- [src/lib/server/plans/agentPlans.ts:76-100](src/lib/server/plans/agentPlans.ts:76)
  — `readdirSync` / `readFileSync` on `~/.claude/plans/*.md` for the
  PlanViewerModal's "global plans" pool. Read-only. Safe.
- [src/lib/server/agents/claudeHooks.ts:53-89](src/lib/server/agents/claudeHooks.ts:53)
  — `writeFileSync(<worktree>/.claude/settings.local.json)`. **Per-worktree**
  not user-global. Safe.
- [src/lib/server/agents/claudeConfigDir.ts](src/lib/server/agents/claudeConfigDir.ts)
  — reads from `~/.claude*` to **seed per-agent copies/symlinks**.
  No writes back to `~/.claude*`. Safe.

No code writes to `~/.claude.json` or any user-global file under
`~/.claude/` outside what claude-code itself does.

### Deploy / CI / scripts — clean

- `deploy/systemd/maw.service` + `deploy/systemd/maw-tmux.service` —
  unit files only; no claude invocation.
- `deploy/fail2ban/*` — fail2ban filters; no relevant calls.
- `~/maw/deploy.sh` (on host, not in repo) — `git pull && pnpm
  install && pnpm build && systemctl --user restart maw`. No
  `claude update`, no `npm i -g claude`. Safe.
- `scripts/*.ts` (`migrate`, `test-adapter`, `bundle-server`,
  `generate-vapid-keys`, `gen-version`) — none spawn claude.
- `.github/workflows/*.yml` — checked in the audit; no `claude`
  invocations. Pnpm + Playwright only.

### Plugins & MCP — could theoretically write, but not under MAW's control

`~/.claude/plugins/` is symlinked into each per-agent config dir by
[claudeConfigDir.ts:71](src/lib/server/agents/claudeConfigDir.ts:71).
If a plugin's install/update rewrites a file all agents share, that's
a kill path too — but MAW doesn't trigger plugin updates; only `claude
plugin add/update` from a user shell does. Out of scope for this fix;
note for the operator runbook.

### Verdict

The integration test is the **only** MAW-owned kill path. Closing
it (Layers A–D) plus the one-line `MAW_TMUX_SOCKET` opt-out in
`TmuxSession.ts` (Layer B) collectively make every existing test
safe on the production host, including the e2e suite by side effect
once its playwright webServer env carries the var.
